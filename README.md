# MPC Master Mixer

Touchscreen mixer project for the Akai MPC Live II.

## Current state

- Browser-based tactile UI prototype in `prototype/index.html` (local demo state only).
- Optional browser Web Audio test tone in the prototype, controlled by the selected track fader/pan/mute/solo and Master level/mute (local synthetic signal only).
- Portable C++14 DSP and mixer-control core with host tests.
- Device-neutral full-duplex host with explicit mono input routing and an
  opt-in linked/unlinked stereo Audio In pair path, driven by an offline test
  backend; the pair's current native path is gain/balance/mute/solo only.
- Framework-neutral mixer presentation snapshots and a validated, sequenced UI command dispatcher (host-side contract only).
- Native audio meter snapshot, UI consumer and framework-neutral presentation adapter.
- ARMv7 hard-float cross-compilation probes and test binaries in GitHub Actions.

The prototype is **not connected to the C++ engine or to live MPC audio/MIDI**. A native UI host, supported display integration, target SDK/sysroot and safe launch path have not yet been established. Do not treat CI cross-compilation as a deployable MPC application.

## Try the tactile browser prototype

Open `prototype/index.html` directly in a modern browser. Select a channel, then press **SIGNAL AUDIO** to start a local 220 Hz test tone. The selected channel's fader, pan, Mute/Solo and the Master fader/Mute affect that browser-generated tone. Press the button again to stop it. Use a low listening level first.

The tone is generated by the browser Web Audio API; it is not MPC audio, does not use the C++ DSP engine, and does not connect to any hardware. While the tone runs, browser `AnalyserNode` measurements drive the selected channel and Master peak/RMS meters; the other channels remain inactive. The VU meter demo remains a separate visual simulation and is disabled when the audio tone starts.

The browser and native offline tests also share five numeric signal scenarios (centre pan, hard-left pan, track mute, Master gain and Master mute). See [`docs/AUDIO_SIGNAL_REFERENCE.md`](docs/AUDIO_SIGNAL_REFERENCE.md). The C++ test measures actual offline engine output; the browser test validates the same equal-power reference calculations, not a bit-for-bit Web Audio render comparison.

## Run the host C++ tests

Requires CMake 3.16+ and a C++14 compiler:

```sh
cmake -S . -B build/host -DCMAKE_BUILD_TYPE=Debug
cmake --build build/host --parallel
ctest --test-dir build/host --output-on-failure
```

Use Debug (or another configuration with assertions enabled): the current test programs use `assert`. The optional host-only DSP benchmark is built as a separate target:

```sh
./build/host/audio_engine_benchmark
```

The benchmark is diagnostic for the build machine only; it is not an MPC performance guarantee.

## Safety boundary

The current work is repository-side. No changes to the stock MPC executable, system services, activation/licensing, audio routing, DRM ownership, framebuffer, touch devices, or root filesystem are part of this project workflow. Hardware validation requires separate explicit authorization.
